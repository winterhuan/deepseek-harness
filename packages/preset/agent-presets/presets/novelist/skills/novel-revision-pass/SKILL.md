# 修订：两轮制，先全局后局部

修订最贵的错误是：在结构有问题的稿子上打磨句子。两轮制强制先处理贵的问题。

## 1. 全局 pass（只看结构，不改字句）

对一卷（或全书）做一次只读诊断，输出问题清单，**先给方案再动笔**：

1. **人物弧光**：对照各小传的「弧光」区——三次推动事件是否都发生了？有没有人物两卷没有自己的场景？
2. **节奏**：连续三章同一冲突原地踏步 / 单章超过 8 千字仍无转折 / 关键转折被塞进章尾两段——逐章标注。
3. **多线平衡**：副线是否在卷内与主线交叉过？有没有一条线连续 5 章零进展（该并线、砍线或插章）？
4. **伏笔账本**：`novel_board_read` 的未回收伏笔逐条判断——回收、改用途、还是删除。删除也是回收（要同步状态板）。
5. **卷尾不可逆事件**：每卷 exit 是否真的不可逆？可撤销的卷尾是伪高潮。

产出物：一份问题清单（编号 G1、G2……），每条附「改法选项 + 推荐」。**作者裁决后**才进入第二轮。

## 2. 修订范围确认与备份

作者点名修订时先确认两件事，再动笔：

1. **范围**：全文重写（基于细纲重写整章，原章只留参考）还是局部修改（只改指定段落，其余不动）。作者说的是章节名而非编号时，用 `fs-search` 按关键词定位章节文件；找不到让作者确认。
2. **备份**：全文重写前，把原文复制为 `chapters/NN-章名-原稿-YYYYMMDD.md`，保证可回退；局部修改依赖 fs 工具的精确 edit，不整文件覆盖。
3. **衔接加载**：局部修改至少加载前一章结尾与后一章开头；全文重写加载细纲与前一章。

## 3. 局部 pass（在冻结的结构上打磨文字）

结构冻结后逐章处理：

1. **场景收束**：每个场景有出口（信息/关系/局势）；出口模糊的场景重写最后两段。
2. **语言指纹**：对话逐句核对说话人声线；两个角色说话方式可互换的段落是重灾区。
3. **冗余**：同章内重复交代的信息删一处；跨章重复的设定交代保留首次，后续改为一笔带过。
4. **开段与钩子**：章首三段不铺陈天气与回顾；章尾钩子逐章核对。
5. **节奏**：整章无变化的长段拆开；关键转折不塞在章尾两段。
6. 逐处用 fs 工具的 edit 做精确修改，整段重写才用 write 覆盖。

## 4. mode=revision 事务（修订的追踪写法）

修订改变已提交章的连续性事实时，用 `novel_track`（action: commit, mode: revision）重提该章事务：

1. 先 `novel_track`（action: check）取当前 stateRevision 写进 expectedRevision；期间状态已变则重读重构。
2. **重算完整记录**：对比旧正文与修订稿，重写该章对未来仍有效的完整 delta（result、characterChanges、foreshadowChanges、timelineChanges）——不能只传本次改动；工具整份重写该章逐章记录，被新正文推翻的结论不保留。
3. **当前值提交**：受影响的角色、伏笔、时间线提交**截至最新已写章的当前值**（从修订章重算到最后一章），不是修订当时的值。核心角色提交重算后的完整快照，不拿单维变化覆盖其它维度。
4. **伏笔**：对同一 ID 更新当前行，不追加历史。修订删除了埋设但后文仍引用该 ID → 先列正文冲突；确认整条线不存在才删除。
5. **时间线双视图**：受影响事件同时更新作者真相与读者已知；删掉的事件显式删除；未揭示事件读者视图不出现（见 novel-continuity-audit）。
6. **退役不进 revision**：retiredCharacters 只能在 append 事务声明；revision 事务原样重交当前全部上下文条目（longTermConstraints、continuityRisks 逐条带上，仍然成立的不能省略——漏写会被工具拒绝或当成退役）。
7. **失败重试**：事务提交失败保留构造好的输入，修正后重跑同一份；期间正文或目标已变 → 丢弃旧输入，按当前状态重新构造。
8. 提交后跑 check 确认派生视图一致；纯措辞调整（不影响连续性事实）不必提交事务。修订导入范围内的旧章时，`importedThroughChapter` 不变。

## 5. 级联检查

修订完成后扫描受影响面：

- 后续章节受影响项逐章标记（「修改第 X 章后，第 X+1 章因 Y 需检查」），交作者决定现在改还是记待办。
- 大范围删除的旧设定 → 检查 `characters/` 小传与 `AGENTS.md` 命名表是否残留引用。
- 用 `fs-search` 检索被改设定/伏笔的关键词，确认后文没有残留矛盾引用。
- 字数对比：修订前后差异 >30% 或 >800 字（取大）时提醒作者；带外处置见 novel-chapter-writing 第 6 节。

## 6. 回写纪律

- 结构级改动 → 先改 `outline.md`（章的 enter/exit、卷结构），再改正文。
- 章节状态随第 3 节事务更新；纯措辞修订（无连续性影响）用 `novel_board_update` 把 status 改为 revised/final。
- 修订改变角色状态/关系时，同步小传「与其他人物」区；核心复用角色走事务快照。
- 局部 pass 改完的每章复扫一遍元信息词与一级禁用词（清单见 novel-chapter-writing 第 7 节与 novel-deslop）。

## 7. 连续改多章

逐章修改，每章独立走「范围确认 → 修改 → 事务 → 级联检查」，不批量跨章同时动笔——前一章的修订结论会改变后一章的改法。

## 8. 与审查的衔接

novel-review / novel-continuity-audit 产出的问题清单是修订的常见入口：按 severity 排序处理，S1 全修，S2/S3 按作者圈定范围修；每条修完在清单上销号。审查发现的事实类问题（伏笔、时间线、角色状态）必须落进第 4 节事务，不能只改正文不改追踪——账实不符比错误本身更贵。

## 9. 何时停止

一轮全局 + 一轮局部后，修订收益进入陡降区。继续打磨的信号只有一个：作者点名的问题。Agent 不发起第三轮自嗨式修订。
