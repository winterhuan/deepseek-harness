# 大纲：卷章结构与节拍

大纲不是章节摘要的堆放处，而是全书的压力测试：在写正文之前用最便宜的方式发现结构问题。

## 1. 三层结构

- **全书层（前提）**：核心冲突 + 结局走向。结局可以模糊，但「这本书为什么值得读完」必须清楚。
- **卷层（幕）**：长篇按卷组织，每卷对应一次大的状态转变（人物得到了/失去了什么根本性的东西）。卷尾必须有不可逆事件。
- **章层（节拍）**：每章一行，格式固定：

  ```
  - [ ] 01-雪夜 — 主角发现坠毁的飞行器；exit：被巡逻队盯上
  ```

  每章写 **enter（进入时人物处境）** 与 **exit（离开时变化）**。只有 enter 没有 exit 的章是要合并的章。

## 2. 剧情单元与卷契约

卷是幕，剧情单元是卷内的叙事批。每卷先写**卷契约**，再拆单元：

- **卷契约**：本卷主推线、单元战果归属、卷尾不可逆事件、本卷可动用的资源与底牌边界。锁定后正文与细纲都不得越过。
- **剧情单元**：单元名、章节范围、单元目标、情绪引擎（读者在这段想看什么）、单元战果。每个单元自带一个结构公式变体；单元之间战果递进、复杂度螺旋上升。
- 补纲/扩纲按单元成批出细纲，不单章零散补。

## 3. 终局储备

`outline.md` 登记两类储备，防「写到后期没牌可打」：

- **终局底牌**：大结局才解锁的翻盘手段（隐藏身份、终极能力、关键人证）。
- **升级台阶**：主角每一阶段的实力/资源层级。

纪律：

1. 每卷只动用该阶段已解锁的台阶；多线齐涨的战果允许，单一绝杀不允许。
2. 想提前动用底牌先过两问：这张牌留给终局还能更大吗？本卷战果不用它能不能成立？
3. 储备被消耗即在 outline.md 勾销；无牌可打时先扩储备再推进。

## 4. 阶段节奏与信息释放

每批（约 3 章）动笔前从卷纲提取四项：本批推进目标、**可释放的信息**、**严禁提前释放的信息**、章尾钩子不能越过的边界。

- 未来揭示计划写在大纲（如「F03 计划第 30 章回收」），不写成时间线既成事实——时间线只登记已发生的事实。
- 批末自检：是否超前、拖慢或偏离阶段节奏；偏离时把补偿动作写进下一章承诺，不靠提前泄露后期信息强行提速。
- 高潮后允许 1–2 章低压过渡与可见的小收益，不连续高压。

## 5. 节拍密度参考

- 长篇单章 3–6 千字，一章承担 1–2 个节拍；一章塞三个以上转折必然赶。
- 每卷 8–15 章；第一卷的前三章必须完成：建立日常 → 打破日常 → 不可回头。
- 每卷至少一条副线（配角/世界面），副线与主线在卷内至少交叉一次。
- 高压/推进章每 3000–5000 字一个情绪爆点；低压/关系/整理章不强求，但每章仍要有往下看的理由。

## 6. 细纲字段

每章细纲至少含以下字段，写正文前不可缺：

| 字段 | 内容 |
|---|---|
| 阶段位置 | 本章处于哪个剧情单元、单元内第几拍 |
| 结构公式 | 本章骨架，如 铺垫→出手→反证→代价 |
| 禁止提前释放 | 本章不能揭示的后期真相、底牌、关系结论 |
| 情节安排 | 主线推进 + 辅线/事件线/感情线（多线并列，标注交叉点） |
| 人物 | 出场顺序、关系变化（本章前 → 本章后） |
| 结尾钩子 | 写到期待成立为止，不透露兑现方式 |

- 无法从已有证据判断的字段写 `[待补充]`，不杜撰副线或关系。
- 细纲是「要发生什么」的契约，不是正文的形状：正文可自由编排叙述顺序，但只能展开细纲已有事件——不得为凑字自造新主线、新角色、新反转。
- 同一要求在多个字段重复出现时只算一个语义点，正文只兑现一次。

## 7. 伏笔登记

伏笔是账本，不是灵感。规则：

1. 埋设时立即登记：一句话内容 + 埋设章节；逐章写作中的伏笔变化随 `novel_track`（action: commit）的 foreshadowChanges 提交，`novel_board_update` 用于事务之外的直接修正：`record_foreshadow`（登记，可带 plannedPayoffIn 与 importance）、`pay_foreshadow`（回收，给 paidoffIn）、`set_chapter_status`（draft/revised/final）。
2. 每条伏笔持有 status（已埋/已推进/已回收）、importance（高/中/低）、plannedPayoffIn（计划回收章）。
3. `outline.md` 的「伏笔登记」区只写重大伏笔的因果链；明细以状态板为准。
4. 未回收伏笔超过 5 条时，优先安排回收章，不再埋新伏笔。

## 8. 修订大纲的信号

出现以下情况先改大纲再动笔：某章没有 exit；连续三章同一冲突原地踏步；某人物连续两卷没有自己的场景；结局需要的新设定超过三处未在前文铺垫。

## 9. 与其他文件的分工

`outline.md` 给人看（作者修订的主场）；`.novel/board.json` 是状态事实来源（工具维护）。两者冲突时，以状态板为准更新大纲，不要反向。
