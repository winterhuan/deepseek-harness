# 人物：小传、弧光与语言指纹

人物小传是写作时的「硬盘」，不是设定集炫技。一个小传的标准是：写正文时不再需要向作者追问这个人。

## 1. 小传文件模板

每个重要人物一个文件：`characters/<名字>.md`。固定结构：

```markdown
# <名字>

## 一句话定位
<!-- 他在故事里的功能：主角的成长压力源 / 道德镜像 / 世界观的嘴替。 -->

## 欲望与恐惧
- 表层欲望（他以为自己要什么）
- 深层恐惧（真正驱动他的东西）
- 两者冲突在哪一章爆发

## 弧光
- 起点 A（开场时的状态与信念）
- 终点 B（结局时的状态与信念）
- A→B 的三次推动事件（对应具体章节）

## 语言指纹
- 句子长度与用词习惯（短句机锋 / 长句绕 / 口头禅）
- 绝不说的话（人物声线的负面清单）

## 与其他人物
- 对谁隐瞒什么；与谁的关系在哪个章节发生变化

## 设定事实
- 外貌锚点（2–3 个反复出现的特征）、能力/资源边界、时间线上的年龄
```

## 2. 弧光的纪律

- 弧光是**信念的变化**，不是遭遇的堆叠。三次推动事件必须各自推翻上一层信念。
- 配角也要有微型弧光（一个决定即可），否则是道具。
- 反派按同样的模板写：他相信自己在做对的事，这一条不成立则冲突不成立。

## 3. 语言指纹的用法

写对话前先回看相关人物小传的「语言指纹」。同一场景两个角色调换说话方式，是连续性审查的高频问题。区分度不足时，给每人一条**结构差异**（如：一个爱用反问收尾、一个从不先说结论），而不是堆口头禅。

## 4. 配角经济

- 功能性配角不建独立文件，集中登记在 `characters/roster.md`：名字、一句话定位、出场章。
- 命名表（姓氏、地名、组织名）由 `AGENTS.md` 统一持有，避免撞名与风格漂移。
- 一个配角被第二次启用前，先补齐 roster 里的一句话定位——复用不是免费的。

## 5. 静态小传 vs 动态快照

两套记录分工明确，不互相替代：

| | 静态小传 `characters/<名字>.md` | 动态快照（novel_track 的 characters） |
|---|---|---|
| 内容 | 人格、欲望恐惧、弧光、语言指纹、设定事实 | identity、location、goal、state、abilities、relationships、knowledge、openThreads |
| 变化频率 | 全书基本不变 | 随章节变化 |
| 读取时机 | 写对话与决策前 | 写正文前确认「他现在在哪、知道什么、正在干什么」 |
| 维护方式 | fs 工具手工修订 | 每章事务提交受影响角色的当前值，工具整份覆盖 `.novel/角色状态/<名字>.md` |

纪律：

1. 只为核心复用角色（主角、对手、反复出场的配角）维护快照；一次性路人不建快照，只在事务的 characterChanges 里写变化。
2. 快照只记当前值，不存履历——变化历史在 `.novel/逐章记录/`。
3. 快照与正文冲突时以正文为准：从冲突章重算到最后一章，提交修正后的完整快照，不拿最后一条单维变化当全状态。
4. 修订旧章导致状态变化时同样重算当前值（见 novel-revision-pass）。

## 6. 角色退役（retiredCharacters）

- 不再复用的核心角色写进事务 delta 的 retiredCharacters：工具删除其快照与 `.novel/角色状态/<名字>.md`，并在逐章记录留档。
- 退役 ≠ 死亡：退场、远行、支线完结都算。退役只表示「从此刻起离开热上下文」，正文与逐章记录不受影响。
- 角色阵亡/退场的当章，变化照常写 characterChanges；不必再交一份马上要删的快照。
- 退役只在 append 事务声明；修订事务必须原样重交当前全部上下文条目，需要退役就放到下一次 append。
- 退役角色重新启用 = 复用不是免费的：先补小传与快照再回场。

## 7. 与状态板的分工

人物关系的**变化**（结盟、反目、知情范围扩大）发生在章节里，落盘在两处：小传的「与其他人物」区（因果与动机）与状态板伏笔（若涉及承诺/秘密的埋设与回收）；核心复用角色的关系当前值同时进事务快照的 relationships 字段。
