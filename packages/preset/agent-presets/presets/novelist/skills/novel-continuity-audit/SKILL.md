# 连续性审查：逐层核对清单

连续性错误是长篇最大的信誉成本。审查在两个时点强制执行：一卷完成时、大修订合并后。审查是**只读**的——发现问题列清单，改动走修订流程。

## 1. 审查输入

审查前固定取四样输入，缺哪样在报告里标注证据不足：

1. `novel_track`（action: check）结果——问题清单本身就是审查线索。
2. `novel_board_read`——伏笔账本、章节状态。
3. 待审范围的全部章节正文（`fs-search` 检索 + 抽样通读）。
4. `outline.md`、`AGENTS.md` 命名表、涉事角色的 `characters/` 小传与 `.novel/角色状态/` 快照。

## 2. 四层核对

### 设定层
1. `AGENTS.md` 命名表中的每个专有名词，在已发布章节中的写法是否唯一（用 `fs-search` 全文检索每个词条）。
2. 能力/资源边界：主角团能否做到 X，以首次确立的章节为准；后文超界即为错误。
3. 世界规则例外：每次例外必须有前文铺垫或在正文中被人物显式惊讶。

### 时间线层
1. 抽取每章的时间标记（日夜、季节、节日、年龄），排成时间轴。
2. 旅行时间：两地移动的耗时前后是否一致。
3. 并行线：两条视角线的日期是否对得上（A 线的三天里 B 线发生了什么）。

### 认知层（最易错）
1. 对每个关键秘密，列出「谁知道、从第几章知道」。检索该秘密相关对话，核对知情者在后续章节的言行——知情者装傻要装得像，不知情者不能间接引用。
2. 死亡/离场人物：不得在后续场景中意外出场或被在场者引用。
3. 动态快照核对：`.novel/角色状态/` 中每个核心角色的 knowledge 与 openThreads，与该角色在正文中的言行对照。

### 伏笔层
1. `novel_board_read` 未回收伏笔逐条核对：埋设场景是否真的写进正文（登记了但没写 = 账实不符）。
2. 每条伏笔的 status（已埋/已推进/已回收）与 plannedPayoffIn 是否与正文证据一致；已推进/已回收的要有对应章节。
3. 已回收伏笔：回收场景是否成立、是否与埋设承诺一致。

## 3. 时间线双视图

`.novel/时间线/` 有两个视图，审查时对照检查：

- **作者真相**：客观事实，含未揭示事件（暗中行动、真实身份、幕后动机）。
- **读者已知**：读者截至最新章的认知。

规则：

1. **未揭示事件不得出现在读者视图**——逐条检查作者真相中的未揭示事件，确认读者视图无泄漏。
2. 揭示状态与揭示章一致：未揭示的事件没有揭示章；已揭示的只能填实际发生的章节。
3. **泄漏检测**：未揭示秘密影响的角色，在已发布正文中的言行是否穿帮——不知情者间接引用、知情者装傻露馅。
4. 未来揭示计划（「计划第 X 章揭示」）写在大纲；出现在时间线既成事实里即为错误。

## 4. 抽查法（全书审查时）

全章通读成本高，按 1/3 抽查 + 全量检索结合：

- 逐章全量做：命名检索、时间标记抽取（机械可查）。
- 抽 1/3 章通读：优先关键转折章、卷首卷尾章、时间跳跃章。
- 抽查发现一处认知层错误 → 该章所在卷全量通读（错误不孤立）。

审查规模大时可以派 `subagent` 分工：每个子代理领明确章节范围与第 2 节的核对清单，**只读约束写进 prompt**（只读正文与设定，不改任何文件）；主会话合并结果、复核 S1 级条目的原文证据。单章/单卷审查不派子代理。

## 5. 严重度分级（S1–S4）

每条问题定级，报告按级排序：

| 级 | 定义 | 处置 |
|---|---|---|
| S1 | 破坏主线、角色动机、世界规则或读者信任 | 优先修 |
| S2 | 明显影响章节效果、留存、节奏或人物可信度 | 本轮修 |
| S3 | 局部质量问题（措辞、轻微格式、局部节奏） | 可排期 |
| S4 | 建议项或风格微调 | 不阻塞 |

## 6. 产出与归档

审查产出问题清单，每条用统一字段：severity（S1–S4）、category（structure/character/prose/consistency/factual/format/causal）、location（文件:行 或 章节/段落）、evidence（原文证据句）、issue、fix。编号 C1、C2……；事实类条目的 fix 只写事实统一方向（「统一为左臂旧伤，并同步冲突处」），不写文学建议。

清单落在 `outline.md` 的临时审查区，修订完成后删除——审查清单是一次性工件，不进状态板。证据不足的项（缺设定、缺大纲）在清单里标注，不猜测。查出的追踪事实错误走 novel-revision-pass 的 mode=revision 事务修正。
