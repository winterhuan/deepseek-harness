# 短剧开发

把创作者的意图变成能持续制造**选择、代价与状态变化**的故事系统。保留创作者的题材、结局与尺度选择；不把流行套路当剧情答案。来源：Drama Skills 0.6.1（MIT），DSH 桥接适配 —— 多集整稿索引/切片用 DSH 可见的 read_file / grep 精确索引与切片，不整篇喂入上下文。

## 先判断入口

1. **只有想法、题材或情绪目标**：完成方向探索，再建立创作简报与故事引擎。
2. **已有梗概、小说或改编材料**：保存来源并先列出已承诺事实、可改范围、来源片段与待确认项。长材料先做语义分段、功能账本和候选分集，不用正则人名/名词命中直接发布剧集或资产；不偷换原意。
3. **方向已定、只需规划分集**：读取既有简报与引擎，直接制作或修订分集地图。
4. **已有单集剧本**：不虚构开发材料。写/改交给 `$short-drama-write`；拆资产或后期制作直接从相应技能进入。
5. **已有多集整稿要生成/补分集地图**：保留原文件，先精确索引建临时 `项目开发/episode-intake-index.json`，让 Agent 按文件实际结构决定边界与本轮批次，工具只做索引/切片/校验，不代写创作判断。

信息足够时直接工作。只有会改变主角、冲突引擎、结局承诺或改编边界的缺口才提问。

## 每次执行

1. **锁定创作者契约**：区分不可改事实/可探索空白/形式约束/目标回报。改动已接受事实先展示语义差异与下游影响，不直接覆盖。
2. **探索真正不同的方向**：方向未定给出少量机制不同的候选（主角策略、对抗来源、代价或持续冲突方式），说明各自的戏剧承诺、主角追求、对抗机制、反复回报、可升级状态、长线终止条件与主要制作负担；让创作者选择并记录取舍。未选方案不进既定事实。
3. **建立故事引擎**：写清压力如何出现与应对、对手如何反制、每轮冲突改变什么、人物目标/筹码/底线/关系压力、什么会终结引擎、以及视觉/声音/场景规模和内容边界。连续剧或人物纵向变化较重时先建只供作者决策的前史储备，再选旧策略开始付出代价的叙事切入窗，不把前史直接倒进首集对白。
4. **把系列运动落到分集**：先保证每集产生局部戏剧结果、相邻集精确交接，再讨论节奏双轨。每集记录进入状态、开场、当集追求、阻力、方向性转折、结果、信息释放、出去的压力与下一集必须继承的事实。集数、钩子类型、反转与高潮位置由创作者与项目决定。
5. **做所有者检查并交接**：引用的集/铺垫/回收可找到且未决项明确；候选确实改机制；每次升级能指出权力/信息/关系/暴露/资源/时间/代价变化；每集先兑现一部分当集承诺再留下具体危险。展示创作者可读的摘要，请创作者接受后再作下游来源。

## 产物与边界

只拥有 `项目开发/` 下的开发产物：`creative-brief.md`、`story-engine.md`、`director-brief.md`（仅候选）、`adaptation-map.jsonl`（长材料改编索引）、`series-arc.json`、`episode-intake-index.json`、`episode-map.jsonl`。不写台词与镜头、不拆资产、不写提示词、不生成媒体、不签发终审。剧本语义交给 `$short-drama-write`。

导演阐述只在创作者需要时产出 `项目开发/director-brief.md` 候选并标明它准备写入的 `visual_direction` / `production_profile` 语义差异；创作者接受后由 `$short-drama` 把选择提升到 creator authority。

## 规则分级

`structural_invariant`（引用/ID/显式状态矛盾的本地验证）；`reviewed_invariant`（升级与兑现是否真实，由 reviewer 拿证据判断）；`craft_default`（可覆盖）；`taste_option`（不得单独阻断）。不要用固定情节点/转折时刻/比例配方替代因果判断。
