# 短剧审查

把可证明事实与内容判断分开，带证据给结论与分派。来源：Drama Skills 0.6.1（MIT）。

## Quick Start
直接读取用户点名的当前文件。需要落盘写 `审查/EP001-审查.md`；独立文件用 `审查/<主题>-审查.md`；只要口头结论时直接回复，不为“完整”包建文件。
每条 finding 含：位置、文件/标题 ID/行号/短引文、影响、必须达到的修订结果、owner、严重程度与规则等级。不建第二套状态/hash/record。

## 审查范围
`source_analysis` / `story_script` / `assets_continuity` / `image_prompts` / `storyboard_keyframes` / `video_prompts` / `production_outputs` / `full_episode` / `delivery_privacy` / `project_calibration`。按范围只读对应资料，不预加载整个项目。

## 工作流
1. **冻结范围**：写清要审哪些文件/章节/镜头/提示词与创作者限制；目标中途变则重读再定。
2. **先查可证明事实**：五文档可见 ID/引用/时长是否一致；对白/动作/声音/画面文字都有画面或者声音承载；人物地点道具状态与镜头起止连续；提示词从准确起点到准确终点；私有输入/凭据/绝对路径/内部流程文本是否泄漏。
3. **带证据审内容**：每个 finding 含位置、必要短引文或冲突事实、观众/制作影响、必须达到的修订结果、owner、严重程度、规则等级；不空说“AI 味”“不够电影感”。
4. **跨文档综合**：`剧本事实 -> 视觉设定 -> 镜头职责与边界 -> 冻结关键帧 -> 视频运动 -> 下一状态`；优先守住原意、知情时机与连续性，不奖励脱离来源的华丽提示词。
5. **结论与分派**：结论取 `APPROVE` / `APPROVE_WITH_NOTES` / `REVISE` / `PROVISIONAL`。按 owner 分组修订要求。本轮交还控制权；多视角对抗可用 subagent 并行——修改与复审只在用户明确请求时开始。

## 严重程度
`blocker`（不安全/不可交付/走错流程）、`major`（破坏剧情理解/连续性/制作结果）、`minor`（具体影响不阻断）、`note`（选择/可选润色）。

## 边界
- 不提交生产、不配置 adapter、不把 Dashboard 操作当生产授权。
- 无法读媒体时明确限制，不从文本/adapter 状态推断一致性、表演、口型、混音或市场表现。
- 生产观察必须绑定准确输入/提示词/参考/配置/结果版本，不泛化成通用规则。
- 审查文件只留最小证据，不复制完整私有输入。
